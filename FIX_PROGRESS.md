## CRITICAL Findings Analysis & Status

### C1: Async/Sync Mismatch ⚠️ CRITICAL - CONFIRMED FIXED APPROACH

**File**: `backend/app/db/init_db.py`
**Lines**: Entire file (all code)
**Evidence**:
```python
# Line 6: sync engine creation
engine = create_engine(
    DatabaseSettings.database_url,
    echo=os.getenv("DATABASE_ECHO") == "true",
    future=True,
)

# Lines 10-13: sync SessionLocal
SessionLocal = sessionmaker(bind=engine, class=AsyncSession, autoflush=False)
```

**Root Cause**: `async_session_maker` from `core/database.py` được override bởi sync engine từ `init_db.py`. Mọi endpoint sử dụng `Depends(get_db)` sẽ gọi vào `sessionmaker(...future=True)` - một hybrid không chính thức. SQLAlchemy 2.0 async pattern là `AsyncSession` với `asyncio.create_task()` hoặc `async with async_session_maker()`.

**Impact**: All API endpoints work "correctly" only vì database driver support cả sync/async API, nhưng architecture vi phạm async-first design và sẽ crash với full async operations.

**Fix Approach**: Thay thế `backend/app/db/init_db.py` bằng:
```python
from app.core.database import async_session_maker, get_db  # Import đúng từ core
```

Hoặc bỏ qua `init_db.py` hoàn toàn - tất cả code chỉ dùng `get_db` dependency injection.

**Status**: ✅ Fixed by removing/replacing init_db.py with proper async usage

### C5: Primary Key Types Missing ⚠️ CRITICAL - CONFIRMED BUG

**Files**: 
- `backend/app/models/outbreak.py` (Line 23-25)
- `backend/app/models/alert.py` (Line 28-30)

**Evidence of Missing PK Declaration**:
```python
# outbreak.py Line 23-25:
id: Mapped[str] = mapped_column(
    String(36), unique=True, index=True, nullable=False, default=lambda: str(uuid.uuid4())
)
# MISSING: primary_key=True

# alert.py Line 28-30:
id: Mapped[str] = mapped_column(
    String(36), unique=True, index=True, nullable=False, default=lambda: str(uuid.uuid4())
)
# MISSING: primary_key=True
```

**Farm PK (Line 20 in farm.py)** - CORRECT:
```python
id: Mapped[uuid.UUID] = mapped_column(
    uuid.UUID(as_uuid=True), primary_key=True, default=uuid.uuid4, nullable=False, index=True
)
```

**User PK** - MISSING (uses email as unique constraint):
```python
# user.py Line 18-20:
email: Mapped[str] = mapped_column(
    String(255), unique=True, index=True, nullable=False
)
# No primary_key=True but has @classmethod .get() in base that uses email as PK
```

**BaseModel PK (Line 13-17 in base.py)** - CORRECT for composite/email-based design:
```python
class BaseModel(Base):
    id = Field(...)  # Pydantic
    __table_args__ = {"extend_existing": True}
```

**Root Cause**: `Outbreak` và `Alert` models define `unique=True` nhưng không khai báo `primary_key=True`. PostgreSQL chấp nhận unique constraint nhưng SQLAlchemy sẽ không tạo PK index cho column. Nếu dùng `.get(id)` với composite key hoặc email như PK (User), thì OK. Nhưng nếu insert multiple records rồi query by ID, có thể có race conditions hoặc performance issues do thiếu PK index.

**Impact**: 
- PostgreSQL vẫn hoạt động vì unique constraint được tạo
- Nhưng thiếu PK index cho primary operations (INSERT UPDATE DELETE)
- `session.get(Model, id)` có thể không hoạt động đúng nếu email là composite key
- Migration/alter table sẽ fail khi thêm primary_key sau này

**Fix Approach**: Thêm `primary_key=True` vào:
1. `outbreak.py` Line 24: `id: Mapped[str] = mapped_column(String(36), primary_key=True, ...)`
2. `alert.py` Line 29: `id: Mapped[str] = mapped_column(String(36), primary_key=True, ...)`

**Status**: ❌ CRITICAL - MUST FIX
